# デザインの基本方針と見本

このスキルは2つの層でできている。

| 層 | 置き場所 | 中身 | 変える人 |
|---|---|---|---|
| 基本方針 | このフォルダ直下の `*.md` | どの見本を使っても守る考え方（何を伝えるか、どう並べるか、どのグラフを選ぶか、色をどう使うか） | 人間（構築時） |
| 見本 | `reference/` | 手本にするスライドの元資料（`source.pdf`）と、そこから抽出した具体的な値（色、余白、文字の大きさ）とスライドの作り | 作り手が自由に差し替える |

見本は常に1つで、置き場所は `reference/` に固定する（中身が変わってもパスが変わらないようにするため）。何が入っているかは `reference/README.md` に書く。推奨の見本は、デジタル庁「ダッシュボードデザインの実践ガイドブック」。

## 最初に：元資料があるか確かめる

このスキルを使い始めるときに、毎回確かめる。

1. `reference/source.pdf`（PDF 以外の資料なら `source.<拡張子>`）があるか確かめる。あれば次の節へ進む。
2. ない場合は、ユーザーに元資料の PDF を送ってもらうよう1回だけ頼む。チャットに添付するか、手元のファイルのパスを教えてもらう。持っていない場合は、`reference/README.md` の取得手順を案内する。
3. 受け取ったら、元のファイル名にかかわらず `reference/source.pdf` という名前でコピーする。元のファイルは消さない。
4. コピーしたファイルが PDF であることを確かめる（`file` コマンドなど）。ページ数とファイルサイズを、`reference/README.md` の版の表と比べる。
5. 一致しないときは、ユーザーに確かめる。同じ資料の新しい版なら、`reference/` の md のページ番号と値を見直す。別の資料なら、下の「見本を差し替える」の手順に進む。
6. 断られたとき、または送ってもらえないときは、元資料なしで進める。基本方針と `reference/` の md だけで作業はできる。元資料は、迷ったときに見るためのもの。

- `source.pdf` は git 管理外なので、コミットしない。

## スライドを作り始めるときに1回だけ：元資料を通して読む

新しいデッキ（1つのスライド資料）を作り始めるときに、元資料を最初から最後まで1回だけ読む。md に抜き出せない全体の雰囲気や、スライドの流れをつかむため。

1. 元資料を全ページ読む。一度に読めるページ数に上限があるときは、分けて読む（例：1〜20、21〜40、41〜59）。
2. 読んだことを、そのデッキの作業記録に書く：読んだ日、`source.pdf` の sha256。
3. 同じデッキの2回目以降のセッションでは読まない。作業記録の sha256 と今の `source.pdf` が違うとき（元資料を差し替えたとき）だけ、もう一度読む。
4. 元資料がないときは、前の節の手順で頼む。それでもなければ、読まずに進める。

- デッキの作業記録をどこに置くかは、デッキを作るスキル（`slide-intake` など）で決める。決まるまでは、デッキのフォルダの `README.md` に書く。
- 読んだあとも、細かい値は md を正とする。元資料は、md に書いていないことで迷ったときに、該当ページだけを開き直す。

## いつ、どれを読むか

| 段階 | 読むファイル |
|---|---|
| デッキを作り始める | 元資料を通して読む（上の節。デッキごとに1回だけ） |
| 骨子を作る（どのスライドを何枚、どの順で） | `principles.md`、`layout.md`、見本の `slide-style.md` の「スライドの種類」 |
| 図表を作る | `charts.md`、`colors.md`、見本の `palette.md`。迷ったら見本の元資料（`source.*`）を開く |
| 仕上げの確認 | `checklist.md`、`accessibility.md` |

- 基本方針と見本が食い違うときは、基本方針を優先する。見本の値は、基本方針の範囲内で使う。
- 見本の元資料に載っている図・文章・ロゴは、スライドに転載しない。参考にするのは考え方と作り。

## 見本を差し替える

```
reference/
├── README.md       何の資料か：出典、取得手順、版（日付・ページ数・ファイルサイズ）、利用条件
├── slide-style.md  スライドとしての作り：スライドの種類、余白、文字の大きさ、色の使い方（実測）
├── palette.md      colors.md の役割ごとの色の値と、白とのコントラスト比
└── source.pdf      元資料。公開リポジトリに入れないため git 管理外
```

1. `reference/source.pdf` を新しい資料に置き換える（PDF 以外なら `source.<拡張子>`）。
2. `README.md`・`slide-style.md`・`palette.md` を、今と同じ見出しで書き直す。値が資料にない項目は「なし」と書き、空欄にしない。利用条件は `license-notice/policy.md` の区分で確かめる。
3. 人間が内容を確認する。
4. `html-build` の `theme.css` と `layout-catalog.md` を、新しい値で見直す。差し替えは構築時の作業で、スライド作成中には行わない（作成中に見た目を変えないため）。

- 元資料の図・文章・ロゴ・組織名の表記は、スライドに転載しない。
- 元資料を加工して作ったファイルには、出典と「加工して作成」の旨を書く。
- 前の見本を残したいときは、git の履歴から取り出す（元資料は履歴にないため、`README.md` の取得手順で入手し直す）。

## 出典

基本方針は、デジタル庁「ダッシュボードデザインの実践ガイドブック」（2026年3月31日更新）https://digital.go.jp/resources/dashboard-guidebook を加工して作成した。ダッシュボード向けの記述を、スライド向けに読み替えている。基本方針は見本を差し替えても使えるよう、特定の資料のページ番号を書かない。ページ番号は、見本のファイル（`reference/` の下）だけに書く。
