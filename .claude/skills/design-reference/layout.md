# レイアウト：スライドの中と、スライドの並び

どの見本を使っても守る配置の考え方。具体的な余白・文字の大きさ・スライドの型は、見本の `slide-style.md` にある。

## 1. 1枚の中の配置

- **視線の流れに沿わせる。** 左上から右下へ、上から下へ、左から右へ。左上に全体を端的に示す情報（最も大きな数字、結論）、右下に最も細かい情報を置く。
- **左上が最も目を引くようにする。** 背景色の濃淡で差をつける。
- **グリッドに沿って置く。** 16:9 の画面を縦横に 2〜6 分割できるグリッドを使い、要素の端をそろえる。
- **条件と結果を近くに置く。** 絞り込みの条件（対象期間、対象地域など）はスライドの上か左に置き、その影響を受ける図表はその下か右に置く（ダッシュボードのフィルターの考え方を、スライド向けに読み替え）。
- **タイトルは上、更新日・出典は下。** タイトルは上端に、更新日・出典は右下に置く（このハーネスでは、ページ番号を右下に置くため、出典は左下。`slide-outline/layout-catalog.md`）。

## 2. スライドの並び

- 最初に全体（結論、全体の数字）、次に内訳や詳細、という順に並べる。
- 1枚に収まらないときは、スライドを分けて「全体 → 詳細」の階層にする。
- 長いスライドでは、今どこにいるかを示す（章の扉、パンくず、工程の帯）。見本の `slide-style.md` の「スライドの種類」を使う。

## 3. 作る順番

1. 骨格：スライドごとに「タイトル・補足情報・グラフの候補」を書いた箱を並べる。
2. 見た目に近い下書き：グラフを配置し、ダミーの数値で全体の見え方を確かめる。意図や議論が必要な点は補足に書く。
3. レビューで直す：要望は「なぜそうしたいか」まで聞き、目的に合うものだけを最小限の変更で反映する。すべてを機械的に反映すると情報が多すぎて一貫性が崩れる。
