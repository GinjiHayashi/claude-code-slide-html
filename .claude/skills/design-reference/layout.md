# レイアウト：スライドの中と、スライドの並び

どの見本を使っても守る配置の考え方。具体的な余白・文字の大きさ・スライドの型は、見本の `slide-style.md` にある。

## 1. 1枚の中の配置（p.23〜25）

- **視線の流れに沿わせる。** 左上から右下へ、上から下へ、左から右へ。左上に全体を端的に示す情報（最も大きな数字、結論）、右下に最も細かい情報を置く（p.23, 24）。
- **左上が最も目を引くようにする。** 背景色の濃淡で差をつける（p.23）。
- **グリッドに沿って置く。** 16:9 の画面を縦横に 2〜6 分割できるグリッドを使い、要素の端をそろえる（p.23, 51）。
- **条件と結果を近くに置く。** 絞り込みの条件（対象期間、対象地域など）はスライドの上か左に置き、その影響を受ける図表はその下か右に置く（p.25 のフィルターの考え方を、スライド向けに読み替え）。
- **タイトルは上、更新日・出典は下。** レイアウトのサンプルでは、タイトルを上端に、更新日時を右下に置いている（p.24, 25）。

## 2. スライドの並び（p.19〜22, 43）

- 最初に全体（結論、全体の数字）、次に内訳や詳細、という順に並べる（p.22, 43）。
- 1枚に収まらないときは、スライドを分けて「全体 → 詳細」の階層にする（p.20）。
- 長いスライドでは、今どこにいるかを示す（章の扉、パンくず、工程の帯）。見本の `slide-style.md` の「スライドの種類」を使う。

## 3. 作る順番（p.19〜21, 26）

1. 骨格：スライドごとに「タイトル・補足情報・グラフの候補」を書いた箱を並べる（p.20）。
2. 見た目に近い試作：グラフを配置し、ダミーの数値で全体の見え方を確かめる。意図や議論が必要な点は補足に書く（p.21）。
3. レビューで直す：要望は「なぜそうしたいか」まで聞き、目的に合うものだけを最小限の変更で反映する。すべてを機械的に反映すると情報が多すぎて一貫性が崩れる（p.26）。
