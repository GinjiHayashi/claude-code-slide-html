# 原則：何を載せ、どう伝えるか

どの見本を使っても守る考え方。骨子を作るときと、仕上げの確認のときに読む。

## 1. 載せる情報を選ぶ（p.18）

| 原則 | スライドでの意味 |
|---|---|
| 目的に則する | 発表の目的に当てはまる情報だけを選ぶ。当てはまらないものは削り、聞き手が判断や行動に移るまでの距離を縮める |
| 分解できる | 全体の数字から、聞き手が読み解ける単位まで分けて示せるようにする（全体のスライド → 内訳のスライド） |
| 違いに気づける | 突出した値や、変化の時期と傾向（上昇・下降）に気づけるようにする |
| 鮮度が高い | 使えるうちで最新のデータを使い、いつ時点の数字かを書く |

## 2. 組み立てる（p.19, 22）

- **骨格から決める。** まず何を何枚、どの順で見せるか（骨格）を決め、文言・色・形・グラフの表現はその後に詰める。骨格が決まらないうちに表現を詰めると手戻りが増える（p.19）。
- **構造を伝える。** 全体から部分へ、階層になるように並べる。最初に全体がわかり、次に詳細へたどり着ける順にする（p.22）。
- **適切な情報量にする。** 1枚に載せすぎない。多いときはスライドを分ける（p.20, 22）。
- **比較対象を出す。** 数字だけでは判断しにくいときは、目標値・平均値・前年の値・前年比などを並べる（p.22）。
- 「複雑な操作を要求しない」（p.22）は、スライドでは「読み解くのに説明が要る図を使わない」と読み替える（このハーネスの解釈）。

## 3. グラフを作る2つの原則（p.39〜41）

**知りたいことを知れる**

| 原則 | 内容 |
|---|---|
| シンプルにする | 冗長なデータや説明、装飾的な表現など、理解に不要な情報を取り除く |
| 意味のある順にする | 大小順・時系列順など、伝えたいことに合った順に並べる |
| 強弱をつける | 重要な情報だけ、色・大きさ・文字の太さを変えて目を引く |
| 待たせすぎない | スライドでは「1枚を読み終えるまでの時間を短くする」と読み替える（このハーネスの解釈） |

**誤解を生まない**

| 原則 | 内容 |
|---|---|
| わかりやすく表記する | 前提知識が要る表現や複雑な文を避け、タイトル・系列名・単位を丁寧かつ簡潔に書く |
| データを定義する | 何を対象に集めたデータか、数値の意味、いつ更新されたかを参照できるようにする |
| 表現を歪曲しない | 軸の範囲を恣意的に決めない。範囲を省略しない。差を誇張・矮小化しない |
| メタ情報を書く | データの出典、更新日、いつ時点の数値か、注釈、免責事項を書く |

## 4. 良い例・悪い例（p.42〜47）

| 良い例（Do） | 悪い例（Don't） | 該当ページ |
|---|---|---|
| 全体の指標を先に置き、その詳細のグラフを続ける | 詳細の要素だけが並んでいる | p.43 |
| 項目を大小順・時系列順など、意味のある順に並べる | 意味もなく五十音順で並んでいる | p.43 |
| グリッド線は最小限。数値と直接関係のない文字は薄い色にする | 目盛線・説明文・小数点以下が必要以上に書いてある | p.44 |
| 平面で描く | 3D、ドロップシャドウなど数値と関係のない装飾 | p.44 |
| 色数を絞り、注目してほしい系列だけ色を付け、他はグレー | 全系列に別々の色を付け、どれに注目すべきかわからない | p.45 |
| タイトルに内容とデータの種類を書く（例：「出荷台数（月次推移）」） | 何を表すかすぐにわからないタイトル | p.45 |
| タイトル・凡例は短く端的に | 長く冗長なタイトル・ラベル | p.46 |
| 凡例をグラフのすぐ隣に、グラフと同じ順で置く | 凡例が離れている、順番がグラフと逆 | p.46 |
| 棒グラフの原点は0 | 原点が0でない | p.47 |
| マーカーの形・線の種類・塗りの模様など、色以外でも系列を区別する | 色だけで区別している（白黒印刷で伝わらない） | p.47 |
