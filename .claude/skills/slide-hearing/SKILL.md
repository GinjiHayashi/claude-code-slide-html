# ヒアリング（slide-hearing）

`slide-intake` で埋まらなかった `decks/<deck-id>/brief.md` の項目だけを聞く（要求文書 6.3）。質問は `questions.md` に固定してある。

## 手順

1. **聞くことを決める**：`node .claude/skills/slide-hearing/scripts/check-brief.mjs decks/<deck-id>/brief.md`
   - 終了コード 2（書式の誤り）なら、先に `brief-template.md` に合わせて直す。
   - 終了コード 0 なら聞くことはない。5 に進む。
   - 「空」の項目と「確認」の行が、聞くことのすべて。それ以外は聞かない。
2. **聞く**：`questions.md` の順番で、1回に3問まで。「確認したいこと」の行も同じ枠で聞く。
3. **答えを書く**：答えをもらうたびに brief.md を書き換える。
   - 答えの言葉をなるべくそのまま書く。言い換えや補足を足さない。
   - 「出どころ」の表に「ヒアリング（YYYY-MM-DD）」と書く。
   - 答えた「確認したいこと」の行は消す。
   - 答えから新しい食い違いや疑問が出たら、「確認したいこと」に足す。
   - 答えの中に、調べないとわからないこと（他社の事例、統計、制度など）があれば、「調査が必要な項目」に足す（下の「調査が要るとき」）。
4. **もう一度チェック**して、1 に戻る。空の項目と確認したいことがなくなるか、人間が「これで進めて」と言うまで続ける。
5. **brief の確認を頼む**：
   1. brief.md の要点（目的、聞き手、結論、長さ、配布先）と、まだ空の項目・「未定」の項目を人間に見せる。`deck_id` もここで見せる。
   2. `node .claude/skills/make-slides/scripts/request.mjs decks/<deck-id> brief.md` で承認を依頼する。
   3. 人間の答えは hook が記録する。承認されたかは `node .claude/skills/make-slides/scripts/gate.mjs decks/<deck-id> outline` で確かめる。
   4. 直してほしいと言われたら、直して 5 をやり直す。

## 調査が要るとき

- 論点と、わかっていれば確かめ方の候補を「調査が必要な項目」に書く。調査そのものは構成の検討（`slide-outline`）で `researcher` に頼む（要求文書 7.3）。
- ヒアリングの答えを決めるのに調査が要るとき（例：「業界の平均と比べたい」と言われ、比べられる統計があるかで構成が変わる）は、`researcher` を論点ごとに呼んでよい。結果は brief.md に書かず、人間に見せて答えをもらう。
- `researcher` がまだない間（構築順序 7 の前）は、「調査が必要な項目」に書くだけにする。
- 検索語に機密の情報（未公開の社名・数値・案件名）を入れない（CLAUDE.md）。

## しないこと

- 埋まっている項目や「なし」の項目を聞き直す。`questions.md` にない質問をする（「確認したいこと」に書いたものは除く）。
- 人間が答えていないことを推測で書く。食い違いを勝手に片方に決める。
- brief.md の承認を自分で判断する。`approvals.yaml` を書く。

## ファイル

| ファイル | 中身 |
|---|---|
| `brief-template.md` | brief.md の書式と、事前記入シートとの対応 |
| `questions.md` | 項目ごとの質問、聞く順番、答えが決まらないときの書き方 |
| `scripts/check-brief.mjs` | 書式の誤り、空の項目、確認したいことを出す |
