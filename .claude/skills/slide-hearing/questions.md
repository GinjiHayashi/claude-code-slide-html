# ヒアリングの質問（固定）

聞くのは次の2つ。

- `check-brief.mjs` が「空」と出した項目：この表の質問で聞く。
- 埋まっているが不備や不足がある項目：下の「埋まっていても聞くとき」に当てはまるものを、AI が「確認したいこと」に書いてから聞く。

不備のない項目と、「なし」の項目は聞かない。

スライドの中身の材料（数値の根拠、費用の額や内訳、試行の詳細、展開案の中身、各スライドに書くことなど）は、ヒアリングでは聞かない。brief.md の「構成で検討すること」に書き、構成の検討で扱う。ヒアリングで決めるのは brief.md の項目だけ。

- 項目の名前は `check-brief.mjs` の出力と同じ。
- 聞く順番：`check-brief.mjs` の出力の上から（空の項目がこの表の順、次に「確認したいこと」の順）。重要そうに見えても順番を入れ替えない。
- 空の項目は「確認したいこと」に書かない（`check-brief.mjs` が出すので、二重になる）。
- 1回に聞くのは3問まで（「確認したいこと」の行も1問と数える）。答えをもらってから次の3問に進む。4問以上あっても、一度に並べない。残りは「ほかに◯問あります」と数だけ伝え、中身は書かない。
- 選ぶ項目は選択肢を示す。自由に答える項目は、例を1つ添える。
- 「信頼して使う資料」は、参考資料（調べ終えた結果、書籍の要約など）が `reference/` にあるときだけ聞く。ないときは聞かずに「なし」と書く。
- 「不要」「入れない」などの答えは「なし」と書く。「まだ決まっていない」は下の「答えが決まらないとき」に従う。
- 発表日が入力からわからないときは、最初の返事で発表日を聞く（`deck-id` の日付を発表日にするため。3問の枠には数えない）。今日の日付で付けた `deck-id` と違えば、`slide-intake/scripts/rename-deck.mjs` で名前を変える（`slide-intake` の手順 1）。
- 副題・章のタイトル・言い回しなどで「案を出して」と頼まれたら、3〜4案を出し、それぞれにねらい（何を強く見せるか、どんな聞き手に向くか）を1行で添える。選ぶのは人間。

## 質問

| # | 項目 | 質問 | 答えの例・選択肢 |
|---|---|---|---|
| 1 | 目的・この資料で決めたいこと | この資料を見た人に、何を決めてほしいですか。決めることがなければ、何を伝えたいですか。 | 例：全部門への展開を承認してほしい |
| 2 | 聞き手と前提知識 | 誰が見ますか。その人たちは、このテーマをどこまで知っていますか。 | 例：部長会。試行のことは知っているが、技術の詳細は知らない |
| 3 | 伝えたい結論（1文） | いちばん伝えたいことを1文で言うと何ですか。見終わったときに、聞き手が言えるようになっていてほしい1文です。 | 例：自動化で月40時間が浮くので、全部門に広げたい |
| 3-2 | 終わったあとの行動 | 見終わったあと、聞き手にしてほしいことはありますか。 | 例：自部門での導入を申し込んでもらう／なし |
| 3-3 | 資料の種類 | この資料は、理解してもらうための解説型ですか。決めてもらう・動いてもらうための提案型ですか。 | 解説型／提案型 |
| 3-4 | 前提知識の割合 | 説明なしで使ってよい用語や考え方を挙げてください。それぞれ、聞き手の何割が説明できそうですか。 | 例：- 月次レポート：10割／- データの自動集計：3割（5割に満たないものは、スライドで説明します） |
| 4 | 発表時間・枚数の目安 | 発表時間か、枚数の目安を教えてください。 | 例：15分・10枚 |
| 5 | 調査が必要な項目 | Claude に調べてほしいことはありますか。当てがあれば、確かめ方（参考になりそうなサイト、社内の資料）も教えてください。 | 例：他社の導入事例（公開されている事例だけ）／なし |
| 6 | 必ず入れる要素・入れない要素 | 必ず入れたいもの、入れてはいけないものはありますか。 | 例：費用は必ず入れる。個人名は入れない／なし |
| 7 | 構成の進め方 | 構成はどこまで決まっていますか。決まっているなら、Claude は並びや内容を変えずに作ります。 | 決まっている／たたき台がある／相談して決めたい |
| 8 | 信頼して使う資料 | 渡してもらった参考資料のうち、すでに調べ終えていて、そのまま信頼して使うもの（原本と照らし合わせなくてよいもの）はどれですか。 | 例：R-003（書籍の要約）は採用。原本との照合は不要／なし |
| 9 | title | 表紙のタイトルは何にしますか。2行にしたいときは、改行の位置も教えてください。 | 例：月次レポート作成の自動化 |
| 10 | subtitle | 表紙の副題はありますか。 | 例：2部門での3か月の試行をもとに／なし |
| 11 | date | 表紙の日付は何日にしますか（発表日など）。 | 例：2026年10月24日 |
| 12 | author | 表紙に所属と氏名を出しますか。出すなら、その文を教えてください。 | 所属と氏名／氏名だけ／所属だけ／なし |
| 13 | contact | 最後のスライドに問い合わせ先を出しますか。出すなら、文とメールアドレスを教えてください。 | 文とメール／文だけ／メールだけ／なし |
| 14 | pdf | HTML のほかに PDF も要りますか。 | 要る／要らない |
| 15 | max_subagents | 調査とファクトチェックで、Claude の分身（サブエージェント）を同時にいくつまで使いますか。多いほど早く終わりますが、使うトークンが増えます。 | 1〜10 の数／おまかせ（3） |
| 16 | factcheck | ファクトチェック（事実の確かめ）を、いつ行いますか。数値や事実が結論を左右する資料（費用、効果の数値、他社の事例など）は「2回」をお勧めします。 | 最後に1回（おすすめ。見た目を直し終えてから1回）／構成のあとと最後の2回（構成のあとに数値と結論を支える事実を確かめ、最後に全体を確かめる） |
| 17 | deck_id | （聞かない。AI が `YYYY-MM-DD-<短い英語名>` で付け、brief の確認のときに見せる） | — |

## 埋まっていても聞くとき

入力から書き写した項目も、AI が次の目で見直す。当てはまれば、何が足りないかを具体的に「確認したいこと」に書く（例：「聞き手が『関係者』とだけあります。役職か部署を教えてください。」）。

| 項目 | 不備や不足とみなすとき |
|---|---|
| 目的・この資料で決めたいこと | 決めてほしいことも伝えたいことも読み取れない（「〇〇について」だけ、など） |
| 聞き手と前提知識 | 誰かはわかるが、どこまで知っているかがない。またはその逆 |
| 伝えたい結論（1文） | 1文になっていない、結論ではなく話題になっている（「〇〇の現状」など）、目的と食い違う |
| 発表時間・枚数の目安 | 時間と枚数が大きく食い違う（例：5分で30枚） |
| 調査が必要な項目 | 何を確かめれば終わりかがわからない（「市場について」だけ、など） |
| 必ず入れる要素・入れない要素 | ほかの項目と食い違う（例：入れないものが結論に含まれている） |
| 構成の進め方 | 「決まっている」「たたき台がある」なのに、構成が入力のどこにもない。構成が目的や結論と合わない |
| title・date・author・contact | 表紙や締めにそのまま出せない（略称だけ、日付の書き方がばらばら、メールアドレスの形でない、など） |

- 見直しの結果は、自分で直さずに聞く。誤字のように意味が明らかなものだけは直してよく、そのときは brief の確認のときに直したことを伝える。

## 「確認したいこと」の聞き方

「確認したいこと」に書かれた行は、上の質問と一緒に（3問の枠の中で）聞く。

| 種類 | 聞き方 |
|---|---|
| 入力どうしの食い違い | 両方の内容と出どころを示し、どちらにするかを聞く。例：「発表時間が、記入シート（R-002）では15分、チャット（10月17日、R-001）では10分になっています。どちらにしますか。」 |
| 入力の意味があいまい | 読み取った内容を示し、合っているかを聞く。例：「『例の件』は、9月の試行のことで合っていますか。」 |
| どこにも入らないメモ | 使い道を聞く。例：「『昨年度の反省を踏まえる』というメモは、スライドに入れますか。」 |

## 答えが決まらないとき

- 本文の項目は「未定」と、決まる見込み（いつ・誰が決めるか）を書く。例：「未定（10月20日の打ち合わせで決まる）」。チェックでは埋まったとみなすので、brief の確認のときに人間に一覧で見せる。
- 先頭の設定（title・date など）は空のままにして、brief の確認のときに「まだ空の項目」として見せる。表紙を作る工程までに埋まればよい。
