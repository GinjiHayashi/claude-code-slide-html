# スライドの型の一覧（layout-catalog）

`outline.md` の各スライドの `layout:` には、この一覧の型の名前だけを書く（D3）。運用時は固定で、スライドごとに型を足したり変えたりしない。合う型がなければ近い型で代替し、`build-log.md` に記録して人間に報告する（9.1）。

- 寸法の単位は px。スライドは 1280×720。名前の付いた値（`slide-x` など）は `theme.css` のトークン。
- 文字数の上限は、文字の大きさと置ける幅から計算した値に1字の余裕をみたもの。英数字は全角より幅が狭いので、全角として数えれば安全側になる。最後はビルド時の検査で、実際の行数をブラウザで測って判定する。
- 図・表・グラフ・流れの中身は `diagram-catalog.md` の型を使う。この一覧は、スライドの枠（どこに何を置くか）だけを決める。

## 1. すべての型に共通すること

| 要素 | 決まり |
|---|---|
| 余白 | 左右 `slide-x`（54）、タイトルの上端 `slide-top`（63）、下端 `slide-bottom`（27） |
| タイトル | 左上。`text-title`（36px）・太字・`primary`。前に縦長の帯（幅 8px、高さは文字の 1.25 倍、タイトルとの間 24px、帯と文字の中心を揃える）。**1行のみ、全角30字まで** |
| パンくず（任意） | タイトルの上に、所属する章の名前を `text-breadcrumb`（16px）・太字・`primary` で書く |
| 本文の開始位置 | タイトルの下 `title-gap`（50） |
| 出典・図の番号 | 左下に `text-caption`（12px）・`label` の色で書く |
| ページ番号 | 右下に「n / N」。base.html が自動で付ける。表紙（`title`）には付けないが、数えるときは表紙も1枚と数える |
| 発表者ノート | `notes:` に書く。スライドには出ない |
| 太字 | 特に伝えたい語句を `**語句**` で囲む。1項目に1か所、1枚に3か所まで（`html-build/components.md` 4.2） |
| 図の数 | 1枚に2つまで。3つ以上は検査で報告し、人間が確認する（`components.md` 4章） |

## 2. 型の一覧

| 型の名前 | 用途 | 枠（必須） | 枠（任意） | 制約 |
|---|---|---|---|---|
| `title` | 表紙 | title | subtitle, date, author | 下の 3.1 |
| `toc` | 目次 | — | title | 項目は書かない。後ろの `section` の title から自動で作る。章の数は8まで |
| `section` | 章の扉 | title | description, topics | 下の 3.2 |
| `title-body` | 文章中心 | title, body | breadcrumb, source | 箇条書きは5項目まで、各項目は2行まで |
| `text-diagram` | 左に文章・右に図 | title, body, diagram | breadcrumb, caption, source | 文章の列は幅 `column`（560）。箇条書きは4項目まで |
| `title-diagram` | 図が中心 | title, diagram | breadcrumb, caption, source | 図は高さ 500 まで（画面の約 70%） |
| `two-column` | 2つを比べる | title, left, right | breadcrumb, source | 左右とも、小見出し1つと箇条書き4項目まで |
| `do-dont` | 良い例と悪い例 | title, do, dont | breadcrumb, body | `do` は上端に `success` の帯、`dont` は上端に `error` の帯。緑と赤はこの型だけで使う |
| `grid-4` | 原則や要点を4つ並べる | title, items（4つ） | breadcrumb | 2×2。各項目は小見出し（全角15字まで）と説明（3行まで）。アイコンは任意 |
| `checklist` | 確認する項目の一覧 | title, items（text, done） | breadcrumb | 2列。済みは青の塗りとチェック、未済みは空の枠と太字（形でも区別する）。8項目まで |
| `closing` | 締め | — | contact, email | 表紙と同じく白地＋下端の横の帯（表紙に合わせる）。「ありがとうございました」。問い合わせ先とメールは構成を決めるときに人間に聞く。なければ書かず、お礼だけを縦の中央に置く |
| `credits` | ライセンス表記 | — | — | license-notice のスクリプトだけが作る。outline.md には書かない |

## 3. 表紙と章の扉

背景は白。章の扉は左端に `primary` の縦の帯（幅 `strip`＝20）、表紙と締めは下端に横の帯（3.1）。全面を濃い青にしない（ユーザーの決定。青の面積が大きいと見づらいため）。

### 3.1 表紙（`title`）

4-5 の見本で案B（下端の帯）に決めた（ユーザーが決定）。章の扉（左端の縦の帯）と形を変え、一目で区別できるようにする。

| 枠 | 書き方 | 上限 |
|---|---|---|
| title | `text-cover`（48px）・太字・`primary` | 2行まで、1行あたり全角22字 |
| subtitle | `text-heading`（20px）・`ink` | 1行、全角50字 |
| date | **必須**。右下に `text-body`（16px）・`label` | 1行。例「2026年10月17日」 |
| author.org | 所属。左下に `text-body`（16px）・`label`（日付と同じ） | 1行、全角40字 |
| author.name | 氏名。所属と同じ `text-body`（16px）・`label`。太字にしない（ユーザーが決定） | 1行、全角20字 |

- 下端に横の帯（`primary`、高さ `strip`＝20）を引く。左端の縦の帯は使わない。
- title と subtitle をひとまとまりにし、左揃え（x=80）で縦の中央に揃える。文字の見た目の中心を合わせるため、0.04 文字分だけ上にずらす（Noto Sans JP での実測）。title と subtitle の間は 16。
- 日付と発表者は、帯の上（下端から 60）に置き、上に罫線（1px、`line`）を引いて区切る。発表者は左、日付は右。
- **日付と発表者は、構成を決めるときに人間に聞いて書く**（ユーザーが決定）。日付は必須。発表者は次のどれでもよい。
  - 所属と氏名：2行で書く（上に所属、下に氏名）
  - 氏名のみ／所属のみ：1行
  - なし：日付だけを右に置く

### 3.2 章の扉（`section`）

4-5 の見本で、章の導入の形に統一した（ユーザーが決定）。左に章の番号・タイトル・説明、右にその章のトピックを置く。

| 枠 | 書き方 | 上限 |
|---|---|---|
| 章番号 | 「CHAPTER 1」の形。`text-heading`（20px）・太字・`blue-600`。**自動で付ける**（outline.md には書かない） | — |
| 進み具合 | 章番号の右に、章の数だけ小さな点（8px）を並べ、今の章を `primary`、ほかを `gray-200` で塗る。**自動で付ける**。章が増えても潰れない | — |
| title | `text-section`（64px）・太字・`primary` | 1行、全角16字 |
| description | その章で話すことの説明。`text-body`（16px）・`ink` | 3行まで |
| topics | 右の列（幅 400）。見出し「トピック」（`text-body`・太字・`label`）と番号付きの一覧（`text-body`・`ink`）。左に細い線（2px、`line`） | 3〜6項目、各全角20字 |

- 左右の列をそれぞれ縦の中央に揃える。「この章のゴール」の枠は使わない。
- 章の扉をどこに入れるかは、枚数で固定せず、構成（outline.md）を作るときに内容に合わせて決める（ユーザーが決定）。

## 4. 型を選ぶ目安

- 結論や主張を言葉で伝える → `title-body`
- 図・グラフ・表を見せる → 説明が要るなら `text-diagram`、図だけで伝わるなら `title-diagram`
- A と B を比べる → `two-column`。正しい・誤りの対比なら `do-dont`
- 同じ重さの要点が4つ → `grid-4`（3つや5つなら `title-body` の箇条書き）
- 章の扉（`section`）と目次（`toc`）を入れるかと、その位置は、枚数で固定しない。構成を作るときに内容に合わせて決め、構成の確認（承認ゲート）で人間が見る（ユーザーが決定）

## 5. 4-5 の見本で決めたこと

- 試作した章の導入・チェックリスト・締めは、すべて採用した（ユーザーが決定、2026-10-17）。章の導入は `section` の形になり、別の型にはしない。
- 表紙（`title`）は、章の扉と形が似すぎていたため、5案から案B（下端の帯、日付と発表者は下）に決めた（ユーザーが決定）。
