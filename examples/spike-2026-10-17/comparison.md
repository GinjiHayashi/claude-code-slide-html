# スパイク S4：描画方式の比較

- 実施日：2026-10-17
- 対象：`spike/outline.md` の3枚（表紙、Mermaid のフロー図、Vega-Lite の棒グラフ）
- 環境：Node.js 22、Chromium（ヘッドレス）、mermaid 12.2.0、vega 6.4.0、vega-lite 6.5.0、vega-embed 7.3.0、Noto Sans JP（@fontsource 5.3.1、OFL-1.1）

## 1. 結論

**方式B（ビルド時に SVG 化）＋日本語フォントの埋め込み（方式C）を推奨する。** オフラインで開け、閲覧環境によって見た目が変わらず、1ファイル 185KB で完結する。

## 2. 比較表

| 観点 | 方式A：表示時に描画 | 方式B：ビルド時に SVG 化 | 方式C：B＋フォント埋め込み |
|---|---|---|---|
| ファイル | `a/deck.html` | `b/deck.html` | `c/deck.html` |
| HTML のサイズ | 5KB（＋閲覧時に CDN から約 6MB） | 33KB | 185KB |
| オフライン表示 | **図が出ない**（Mermaid のソースが文字で出る） | 表示できる | 表示できる |
| 外部への通信 | CDN 4件 | 0件 | 0件 |
| 閲覧環境による見た目の差 | 大きい（フォントも図の配置も閲覧時に決まる） | 中（図の配置はビルド時に固定。文字は閲覧者のフォント） | 小（フォントも同梱） |
| はみ出し検査・PDF 化 | 描画を待てば可能 | 可能 | 可能 |
| PDF のサイズ | 280KB | 280KB | 216KB |
| ビルド環境に必要なもの | なし | Node.js、Chromium | Node.js、Chromium、フォントのサブセット化ツール |
| 配布物に含まれるライブラリのコード | Mermaid、Vega など（CDN 経由） | なし（生成した SVG だけ） | なし（フォントのサブセットを含む） |

## 3. フォントの確認結果（R3）

| 項目 | フォントを埋め込まない（B） | Noto Sans JP を埋め込む（C） |
|---|---|---|
| この環境での表示フォント | WenQuanYi Zen Hei（中国語向けの代替フォント） | Noto Sans JP |
| 表紙タイトルの幅 | 564px | 560px |
| Mermaid のノード「業務システム」 | 「業務システ／ム」と2行に折り返す | 1行に収まる |

- 同じ文章でも、フォントによって幅や折り返し位置が変わる。フォントを固定しないと、検査に合格しても閲覧者の環境ではみ出す可能性がある。
- 使っている文字（210文字）だけに絞ると、フォントは約 150KB（通常体と太字）。全文字を埋め込むと数MB になる（推測。サブセット前のファイルの合計からの見積もり）。
- **Mermaid は、フォントの読み込みが終わってから描画しないと、ノードの枠がフォント読み込み前の文字幅で作られてずれる。** ビルドでは `document.fonts.ready` を待ってから描画する。

## 4. 試作で見つかった注意点（型・ビルドの決まりに入れる）

| # | 内容 | 対策 |
|---|---|---|
| 1 | Mermaid の図がとても小さく描かれる | `flowchart.useMaxWidth: false` にし、CSS で図の枠いっぱいに広げる |
| 2 | Vega-Lite の棒が名前順に並ぶ | `sort: null` を付ける（書いた順にする） |
| 3 | Mermaid のノードで日本語が不自然な位置で折り返す（「ダッシュボー／ド」） | 型の制約（ノード名の文字数の上限）や、折り返し幅の設定で対処する。設計時に決める |
| 4 | フォント読み込み前に描画すると枠がずれる | ビルドでフォントの読み込みを待つ |
| 5 | この環境からは CDN に接続できない | 方式B ならビルドにも閲覧にも CDN は不要（ライブラリは npm から取得） |

## 5. 決めること（S5）

| 論点 | 推奨 | 根拠 |
|---|---|---|
| Q1：スライドの仕組み | A（自前の最小限の HTML/CSS/JS） | 約130行の HTML ファイル1つで、16:9 の枠、発表モード、ページ送り、印刷の改ページが動いた |
| Q7：図のライブラリ | Mermaid と Vega-Lite を採用 | 日本語を含めて描画でき、ビルド時の SVG 化もできた |
| Q9：描画のタイミング | ビルド時（方式B） | オフラインで開け、外部通信が0件で、D8（1ファイルで完結）を満たす |
| R3：フォント | Noto Sans JP（OFL-1.1）を、使う文字だけにサブセット化して埋め込む | 閲覧環境による差がなくなる。サイズの増加は約 150KB |

### 未確認の点

- OFL-1.1 のフォントを HTML に埋め込んで配布する場合の表記方法（推測：OFL は文書への埋め込みを認めているが、表記の要否は 12章のライセンス処理で確認する）。
- フォントのサブセット化は、今回は Python の fontTools で行った。R13（スクリプトを Node.js に統一）に合わせるなら、Node.js のツールで同じことができるかを確認する。

## 6. 追加：S4b（HTML/Tailwind の部品で作り直し）

- ファイル：`d/deck.html`（163KB、フォント込み）、組み立て `d/build.mjs`、テーマ `d/theme.css`、ビルド `d/build-d.sh`
- 見比べ：`compare-c-d.png`（左：Mermaid・Vega-Lite、右：HTML/Tailwind）
- 検査：通信を遮断した状態でエラー0件、外部通信0件、はみ出しなし、PDF 135KB、ページ送り動作
- 棒の長さはスクリプトがデータから計算（40 と 6 の棒の幅の比は 0.15 で、データと一致）

| 観点 | C：Mermaid・Vega-Lite | D：HTML/Tailwind の部品 |
|---|---|---|
| 見た目の作り込み | 既定のテーマのまま。細部（角丸、余白、強調）を変えにくい | トークンと部品で自由に作り込める |
| 見た目の統一 | ライブラリごとにテーマ設定が別 | `@theme` のトークン1か所で全体に効く |
| 複雑な関係図（分岐・合流） | 自動で配置できる | 不向き（Mermaid を残す） |
| 日本語の折り返し | 不自然な位置で折れる | `word-break: auto-phrase` で文節単位で折り返せた |
| ビルドに必要なもの | Chromium（描画） | Tailwind CLI（CSS 生成）。描画に Chromium は不要（検査と PDF には使う） |

### 注意（設計時に決める）

- S03 の「1/7」のような強調表示は、データから自動で計算して出した。数値の主張を部品が勝手に増やすことになるため、本番では強調する値も `outline.md` に書かせ、人間の承認とファクトチェックの対象にする。
- `word-break: auto-phrase` は Chromium 系のブラウザでの機能（推測：他のブラウザでの対応状況は未確認）。
